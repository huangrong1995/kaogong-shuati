# AI 错题能力诊断 —— 设计文档

日期：2026-10-18
状态：待评审
范围：新增「能力诊断」功能（雷达图能力矩阵 + AI 薄弱点诊断 + 针对性训练），错题本体系内扩展。

## 意图与 Why

用户刷题积累了大量错题，但只能看到「错题列表」，无法形成**结构化的能力认知**：六大模块各自水平如何？离上岸还差多远？薄弱环节具体在哪个考点、方法论上出了什么问题？怎么针对性补？

本功能把三件事串成一条闭环：
1. **看清现状**：雷达图展示六大模块正确率 vs 达标能力线
2. **听 AI 诊断**：AI 基于错题清单 + 考点分布，定位到「大模块 → 子模块 → 知识点」的薄弱项，给出方法论建议
3. **立刻行动**：针对薄弱考点一键出题，进入专项练习

## 目标 / 非目标 / 反目标

**目标**
- 雷达图：6 轴（常识判断 / 言语理解与表达 / 判断推理 / 数量关系 / 资料分析 / 政治理论，即 `FENBI_TREE` 顶级 group），画用户实际正确率 + 达标能力线
- 达标线按目标分数反推，按模块题量权重差异化
- AI 诊断细化到「大模块 → 子模块 → 知识点」，如 判断推理 → 图形推理 → 笔画数
- 薄弱考点提供「针对性训练」按钮，复用现有专项练习抽题链路

**非目标**
- 不改变做题/判分/错题本现有逻辑与返回结构
- 不做申论/综应的能力矩阵（仅行测六大模块）
- 不做题库二次标注（不改 `question_categories`，知识点二级定位用启发式分类）

**反目标（做了就算失败）**
- AI 编造能力数据：能力矩阵必须来自真实做题记录，AI 只做解读
- 达标判定不透明：能力线的折算公式必须可解释、可在设置页调整
- 破坏双端 1:1 契约：任何新增 API 返回结构必须 server 与 local-handler 逐字段一致
- 引入新运行时依赖：雷达图用 canvas 手绘，不引第三方图表库

## 约束

- **零依赖**：前端图表手绘；后端只用 node 内置模块。唯一 npm 依赖 `sharp`（与图表无关）。
- **双端 1:1**：`server.mjs` 与 `lib/local-queries.mjs` / `public/local-handler.js` 的 SQL 与组装函数逐字段一致，`app.js` 零改动约束（新增功能例外，见「前端」）。
- **题库只读**：`tiku.db` / `tiku-index.db` 只读；能力矩阵实时从 `practice_records` 聚合，不落新派生表。
- **AI 实时读库**：新增智能体配置存 `ai-config.db`，每次调用实时读 `getAgent()`，改完即生效；未配置 api_key 时返回可读降级提示。
- **版权**：分析数据只用于个人备考，不做任何商用/二次分发。

## 数据基础（已勘察确认）

| 数据 | 说明 |
|---|---|
| `question_categories` | tiku-index.db，5.4 万行：`question_id → {subject, category, sub}`。`category`=大模块（判断推理等），`sub`=子模块（图形推理等）。与 FENBI_TREE 第二级同口径。 |
| `practice_records` | practice.db 做题记录：`question_id / subject / chapter / is_correct / selected / group_key / sub_key / archived`。错题 = `is_correct=0 AND archived=0`。 |
| `getPaperPool()` | server.mjs 组卷池，`byKey` 按 `${subject}|${category}|${sub}` 抽题；`/api/practice` 端点已支持 `group`/`sub`/`subject`/`difficulty` 过滤 → 针对性训练直接复用。 |
| `FENBI_TREE` | 三级知识树：大模块 → 子模块 → 知识点（leaves）。行测 6 group、每 group 有 subs、subs 有 leaves。 |
| `callAgent(agent, userContent)` | AI 调用统一入口，system_prompt + skill 注入（resolveSkill），OpenAI 兼容协议。 |

## 已定决策

### 1. 能力线与目标分数反推（C 方案）

行测满分 100、答对计分不扣分，**达标正确率 ≈ 目标分 ÷ 100**。预设三档（进面线调查见附录 A），设置页可调：

| 档位 | 国考行测 | 福建省考行测 | 达标正确率 |
|---|---|---|---|
| 打底 | 62 | 65 | 62% / 65% |
| 稳妥上岸（默认） | 68 | 72 | 68% / 72% |
| 高分挑战 | 75 | 78 | 75% / 78% |

用户可自由选择考试目标（国考 / 福建省考）与目标分（含自定义值）。

### 2. 能力线按题量权重差异化

- 题量权重 `w_i` = 模块 i 近十年题量 ÷ 六大模块总题量（从 `question_categories` 实时统计，随库更新）
- 模块达标线：`line_i = clamp(T + k · (w_i − w̄), 下限, 上限)`
  - `T` = 目标正确率，`w̄` = 平均权重，`k` = 差异化强度（默认 0.35，可调）
  - 下限 0.50、上限 0.90
- 效果：言语/判断等大分模块达标线更高（拿分基本盘），数量/时政等线略低（保底即可）
- 达标判定：模块实际正确率 ≥ line_i 即达标

**能力线折算对用户透明**：设置页展示当前目标分 → 各模块达标线的换算结果。

### 3. 知识点二级定位（启发式）

`question_categories` 只到子模块级。向下细分到「图形推理 → 笔画数」用**启发式关键词分类**：

- 新建 `lib/leaf-classifier.mjs`（前后端共用，`public/lib/leaf-classifier.js` 为副本）
- 输入：题目（题干 + 答案解析文本），输出：命中的知识点 leaf 名（来自 FENBI_TREE 该 sub 的 leaves）或「未细分」
- 依据：答案解析文本通常明确提及考点（「笔画数」「对称轴」「奇点」「封闭面」…），加题干关键词匹配
- 每 sub 配关键词表；无命中的归「未细分」（雷达图/AI 诊断中如实标注）
- **用于**：(a) AI 诊断时把错题按知识点归类传给 AI；(b) 针对性训练可按知识点过滤抽题（`/api/practice` 扩展可选 `leaf` 参数，关键词二次过滤）

### 4. AI 诊断角色

新增智能体「错题诊断顾问」（`role: 'wrong-diagnosis'`，id 顺延）：

- 默认配置：独立 `base_url`/`api_key`/`model`，存 `ai-config.db`；`skill` 注入考公方法论 skill（沿用现有）
- **输入（后端组装）**：
  1. 六大模块能力矩阵 JSON（正确率/题量/达标判定）
  2. 未达标模块的错题清单（题干摘要 + 你的答案 + 正确答案 + 大模块/子模块/知识点 + 解析摘要，限量）
- **输出**：按模块分节的诊断：薄弱子模块确诊、知识点分布、原因假设、方法论建议（引用 skill）、优先级建议
- 未配置 api_key → 返回可读降级提示（同 `/api/ai/explain` 模式）

### 5. 新 API（双端 1:1）

| 端点 | 用途 | 返回核心字段 |
|---|---|---|
| `GET /api/ability` | 能力矩阵（不依赖 AI，离线可用） | `{ groups: [{ group, total, correct, rate, line, met, subs: [{ sub, total, correct, rate }] }], weights, target }` |
| `POST /api/ai/diagnose` | AI 诊断（内部组装能力矩阵 + 错题 → callAgent） | `{ content, model, error? }`（复用 explain 响应形态） |

- server 端：`server.mjs` 新端点；聚合 SQL 注释「与 local-queries.mjs 1:1」
- local 端：`lib/local-queries.mjs` 加 `abilityMatrix()` 同构函数；`public/local-handler.js` 加对应 handler；`public/ai-local.js` 加 `aiDiagnose()`
- 针对性训练不新增端点：前端带 `group/sub/leaf` 调现有 `/api/practice`

### 6. 前端

- 入口：错题本 tab 页新增「AI 能力诊断」按钮（主入口）；首页快捷入口可选加一项
- 新视图 `renderAbility()`：
  - 顶部：目标设置（国考/省考/自定义 + 目标分档位）+ 达标线换算说明
  - 雷达图：canvas 手绘，6 轴实线=实际正确率，折线=达标线（两套不同视觉），图例说明
  - 模块卡：每模块正确率/题量/达标徽章；点击展开 → 子模块正确率条 + 知识点分布
  - AI 诊断区：按钮触发 `/api/ai/diagnose`，loading → 输出分节诊断（markdown 渲染，复用现有容器）
  - 针对性训练：未达标模块/子模块/知识点旁「针对性训练」按钮 → 调 `/api/practice` → 复用现有 `enterQuiz` 做题流程
- `store.state.view` 状态机 + `renderAbility` 加入 `setView` 分发
- 雷达图组件：`public/lib/radar-chart.js`（canvas，6 轴，传入 values/line 数组）

### 7. 降级与边界

- 无错题记录：能力矩阵全空 → 显示「暂无数据，去刷题」空态，AI 诊断禁用
- 做题量过少（某模块 < 5 题）：该轴显示「数据不足」，不参与达标判定（避免小样本误判）
- AI 调用失败/超时：降级显示统计结论（能力矩阵仍在），提示 AI 未配置或失败
- 本地模式 AI 未配置：同 server 降级提示

## 留给实现者（builder）

- `k` 差异化强度系数、`clamp` 上下限的最终取值（默认 0.35 / 0.50 / 0.90，可在设置页调整）
- leaf 关键词表的具体词项（需覆盖图形推理/数量关系/判断推理/言语/资料/常识的常用考点表述）
- 雷达图 canvas 的具体绘制参数（网格层级、配色跟随主题深/浅）
- 错题清单送入 AI 的截断策略（每模块限量、总 token 上限）
- 设置项存放位置（复用 `ai-config.db` 的 config 表 or localStorage；倾向 localStorage 简单化，双端一致）

## 附录 A：进面分数调查（2026-10-18 搜索）

**国考 2025**
- 官方合格线：中央/省级行测≥55、总分≥110；市地/县区行测≥50、总分≥95（国家公务员局）
- 实际进面分：税务/海关普通岗 120-135 总分（行测占一半 → 约 60-67 分），热门岗（北上广）130+ 个别 140+

**福建省考（2024-25）**
- 官方合格线：A 类省直行测≥60，市直/县乡≥50；B 类总分≥100
- 实际进面分：省直/厦门行测 68-72，地市 60-65，乡镇 55-62；热门岗竞争比 100:1+，需行测 65+

**折算**：行测满分 100，目标正确率 ≈ 目标分 ÷ 100。三档预设取「进面平均线下沿 / 中位 / 中上」。

## 附录 B：评审核验与补充决策（2026-10-18 builder-check）

评审对照代码核验了文档的数据基础，提出 6 点。处理如下：

### B1. 能力矩阵科目范围 —— 我做主
行测与职测共用同一棵 `FENBI_TREE`（`question_categories` 里两者 category/sub 同口径），但目标分表是行测专属（国考/福建省考）。决定：**矩阵只聚合 `subject = '公务员·行测'` 与 `'事业编·职测'` 两种**（都映射到同一棵树，权重合并统计），申论/综应排除。用户设的是行测目标分，职测记录并入权重不影响解读。

### B2. 矩阵计数口径 —— 我做主
评审指出 `practice_records` 是「每次作答一行」，同一题可能先错后对；且 `archived=1` 行是否计入未定义。决定：**能力矩阵按每次作答计**（与 `/api/records/stats` 现有口径一致，双端 1:1），`archived=1` 的作答**不计入**（同错题口径）；正确率 = 非归档作答中 `is_correct=1` 占比。达标判定按该率。做题量不足（<5 次作答）的模块显示「数据不足」，不参与达标。

### B3. 知识点二级定位的实际粒度 —— **用户拍板：自定义细分标签（方案二）**

评审验证 `FENBI_TREE` 图推 leaves 是粗粒度（位置/样式/属性/数量规律…），没有「笔画数」叶子；且资料分析全部 subs 的 `leaves: []`。用户选择方案二：**新建一张考点细分标签表，细分到更细粒度（笔画数/对称/面数…），资料分析也建自定义标签**。要点：

- 数据基础仍是 `question_categories`（已把题归到 `大模块→子模块`），在此基础上子模块内部做关键词细分
- 分类依据：**解析文本优先**（粉笔解析明确写「题干图形笔画数均为 3」这类考点），题干兜底（图形题题干常是「从所给四个选项中…」过于笼统）
- 标签组织：树叶子为一级（数量规律），其下细分标签为二级（笔画数/面数/线条数…）。资料分析：子模块（增长/比重/平均数/倍数/综合）下自定义细分标签
- `lib/leaf-classifier.mjs`（前后端共用）暴露 `classifyLeaf({ sub, content, analysis }) → leafLabel | '未细分'`，每子模块配关键词表（含别名变体）
- 用于：(a) AI 诊断错题按细分标签归类；(b) 针对性训练按细分标签过滤（`/api/practice` 加 `leaf` 参数）
- 词表初版由实现阶段基于真题统计建立，可后续追加；词库够用时再考虑并入 `tiku-index.db` 落库（本期不落库，实时分类）
- 边界：无命中的题归「未细分」，雷达图/AI 诊断如实呈现，不硬猜

### B4. `/api/ability` 的目标分来源 —— 我做主
决定：**前端在请求时把 `target`（目标正确率，已由目标分÷100 换算）+ `exam`（guokao/fujian）作为 query 传入**，后端返回 `groups[].rate + line`（line 由后端按权重与公式算出）+ `met`（rate≥line）。前端只传值不重复实现公式，双端同构。

### B5. `/api/practice` 的 leaf 过滤 —— 我做主
评审确认 `/api/practice` 现无 `leaf` 参数（只认 subject/chapter/chapters/group/sub/mock/year/difficulty/n/custom）。决定：**双端各加可选 `leaf` 参数**：抽题 SQL 在 `question_categories` 按 `group+sub` 取候选后，用 `leaf-classifier` 的关键词对题干/解析做二次过滤；若命中数 < 目标数则回退（只返回命中部分 + 前端提示「该考点题量不足」）。方案一（现树）时 leaf 取树叶子；方案二时取自定义标签。

### B6. 本地端 AI 诊断的接线 —— 实现选择
评审指出 `public/ai-local.js` 的 `createAiApi({ request, tiku, query })` 拿不到 IndexedDB 记录（错题清单与矩阵在记录里）。决定：**本地端由 `local-handler.js` 组装矩阵+错题清单并直接调用 `ai-local.js` 暴露的 `diagnose()`**（传入组装好的 payload），`createAiApi` 不感知记录存储；与 server 端「后端组装 payload → callAgent」对偶。此为实现细节，写进实现计划即可。
